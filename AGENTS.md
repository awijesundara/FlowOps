# FlowOps Development Contract

Before planning or changing FlowOps, read `PRODUCT_BACKLOG.md` completely.

- Treat that backlog as authoritative scope and phase order.
- Identify the exact epic/story for every change before implementation.
- Do not bypass unfinished P0 stories in the active phase for later-phase work.
- Update story status only when acceptance criteria are supported by tests.
- Keep original FlowOps branding and code; external products are behavioral and
  workflow references, not sources for copied assets or trade dress.
- Preserve ServiceOps as the ITSM/governance system and FlowOps as the live
  orchestration system.
- Every delivered change requires regression tests and a healthy Docker preview.
